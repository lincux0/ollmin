# Ollmin 重大技术决策记录

> 本文保留既有技术决策记录，当前产品版本为 `1.2.0`。它不是待办清单；新方案如果要改变这些边界，应先补充新的决策记录并说明迁移成本。

## 决策状态

- **Accepted**：已经实现并作为当前基线维护。
- **限定范围**：只在特定档位或特定用户操作下生效。
- **保留**：当前不改变，但未来可以在新决策中替换。

## D-001：使用 Tauri 2 + React 19 + TypeScript + Vite

**状态：Accepted**

**背景**：Ollmin 需要 Windows 桌面窗口、原生窗口控制和本地 Rust 能力，同时希望界面迭代效率接近 Web 前端。

**决策**：桌面壳使用 Tauri 2，界面使用 React 19、TypeScript 和 Vite；Rust 代码作为 Tauri library crate，前端通过 `@tauri-apps/api` 调用命令。

**原因**：

- Tauri 使用系统 WebView，发行体积和常驻资源通常小于捆绑完整 Chromium 的桌面方案；
- React/TypeScript 适合当前单页聊天状态和组件测试；
- Rust 可以集中处理本地 HTTP 流、取消、SQLite 和错误边界；
- 前后端职责清晰，后续可独立替换局部实现。

**代价**：需要同时维护 TypeScript 类型和 Rust serde 类型；浏览器直接预览没有 Tauri `invoke`，不能把 Vite 页面当作完整客户端运行。

## D-002：Rust 作为 Ollama 请求网关

**状态：Accepted**

**背景**：如果由 WebView 直接访问 Ollama，跨域、请求取消、流解析和错误显示会受到运行环境影响，也更容易把远程地址能力带入界面。

**决策**：所有 Ollama 请求通过 `src-tauri/src/commands.rs` 的 Tauri command 发起，前端只调用 `src/api.ts` 的封装函数；命令层依赖 `platform::runtime::ModelRuntime`，不直接拼接本机 URL。

**当前通路**：

- `GET /api/version`：连接状态；
- `GET /api/tags`：模型列表；
- `GET /api/ps`：已加载模型；
- `POST /api/generate`：用户显式点击的预热；
- `POST /api/chat`：聊天和诊断。

**代价**：新增一个 API 需要增加 Rust command、前端封装、权限/测试和错误映射，不能只在 React 中临时调用。

## D-003：只连接本机 Ollama

**状态：Accepted**

**决策**：Ollama 基地址固定为 `http://127.0.0.1:11434`，请求由 Rust 后端发起；WebView CSP 不允许直接连接 Ollama。设置页不提供任意远程 URL、账号、云端 API 或遥测开关。

**原因**：项目面向低性能设备和本地模型，核心价值是降低本地客户端额外开销。使用已下载的本地模型时，推理在本机进行；选择 Ollama 云端模型时，本地服务仍可能将请求转发到云端，固定本机地址不等于模型来源过滤。

**代价**：不支持远程 Ollama、局域网共享实例或 OpenAI 兼容服务。若未来开放连接范围，必须单独设计地址校验、风险提示和隐私策略，不能简单把基地址改成用户输入。

## D-004：采用 Ollama 原生 `/api/chat` NDJSON 流

**状态：Accepted**

**决策**：聊天主通路使用 Ollama 原生 Chat API，启用 `stream: true`，Rust 用字节缓冲区按换行重组 NDJSON；不把 OpenAI 兼容接口作为核心抽象。

**原因**：原生响应包含 `thinking`、`done_reason`、加载/提示词/生成统计等 Ollama 语义，适合 Qwen3 和本地性能诊断；按字节缓冲可以处理一个 JSON 被拆成多个网络块或多个 JSON 共存于同一块的情况。

**代价**：客户端依赖 Ollama 原生字段和行为，不能直接切换到任意兼容 API；兼容性处理应集中在 Rust 解析层。

## D-005：思考与正文从协议层分开传递

**状态：Accepted**

**决策**：Rust `ChatStreamEvent` 同时携带 `content` 和 `thinking`，前端分别维护并渲染；快速档直接发送 `think: false`，平衡/推理档允许思考内容折叠显示。

**原因**：思考 token 会影响用户感知等待和输出统计；混入正文会破坏 Markdown 和复制结果，也无法区分“模型在思考”与“模型没有输出”。

**代价**：流状态、消息类型、落库和导出都要处理两个文本通道；对不支持 thinking 的模型只能依赖 Ollama 返回的空字段或错误提示。

## D-006：三个性能档位是显式请求契约

**状态：Accepted**

**决策**：前端 `PERFORMANCE_PROFILES` 与 Rust `profile_for_mode` 同步维护以下参数：

| 档位 | `think` | `num_ctx` | `num_predict` | 快速历史预算 |
| --- | ---: | ---: | ---: | ---: |
| 快速 | `false` | 4096 | 2048 | 2048 token |
| 平衡 | `true` | 4096 | 768 | 3072 token |
| 推理 | `true` | 8192 | 2048 | 6144 token |

**原因**：档位是可解释的 Ollama 请求配置，而不是无法验证的“加速按钮”；用户可以根据任务选择速度、上下文和推理成本。

**代价**：两个实现必须保持一致；修改参数需要同时更新前端单元测试、Rust 测试和性能文档。快速档的 `num_predict=2048` 是输出预算上限，不保证每次都生成到该长度。

## D-007：快速模式按完整对话轮次裁剪历史

**状态：Accepted / 限定范围**

**决策**：只有快速档强制应用历史裁剪：保留系统消息、最近用户消息，再从新到旧加入完整的用户/助手轮次；不截断单条消息，不用摘要替代旧历史。

**原因**：低配设备上上下文预填充和 KV cache 会直接影响首字延迟；保留完整轮次可以避免只把孤立的助手消息或孤立的用户消息发送给模型。

**代价**：快速档可能丢失早期对话背景；前端估算只用于裁剪，最终 token 数仍以 Ollama `prompt_eval_count` 为准。自动摘要会引入额外模型调用，因此暂不加入主路径。

## D-008：前后端都做流事件节流，但保证首字和终止及时

**状态：Accepted**

**决策**：Rust 侧按 24 ms/16 KiB 批处理流事件，首个可见增量、错误、取消和终止包立即刷新；前端 `streaming.ts` 再按动画帧合并 React 更新，并对终止状态同步刷新。

**原因**：逐 token 触发 Tauri event、React 状态更新和 Markdown 重渲染会增加 UI 主线程工作；完全等待批量又会让用户看不到首字或尾部状态。

**代价**：事件不是一 token 一事件，诊断中的“解析事件数”和“发出事件数”不同；取消和迟到事件需要依赖请求 ID、序列号和调度清理保持一致。

## D-009：默认单请求，不允许并发聊天

**状态：Accepted**

**决策**：`ChatState.active` 只保存一个活动请求；`start_chat` 在已有请求时返回错误；每个请求拥有自己的 `CancellationToken`，停止只能取消相同 request ID。

**原因**：低显存/低内存设备并发会扩大模型和上下文占用，可能造成换入换出，反而使所有请求变慢；单请求也简化了消息顺序和指标归属。

**代价**：用户不能并行向多个模型发问，也没有后台队列；若未来增加队列，必须保留资源上限、取消语义和公平性测试。

## D-010：SQLite 单文件 + 版本化迁移

**状态：Accepted**

**决策**：使用 `rusqlite` bundled，在 Tauri 应用数据目录创建单个 `ollmin.sqlite3`；所有 schema 变更从 `storage::migrate` 进入，当前 schema 版本为 9。

**原因**：会话、消息、设置和指标都是本地结构化数据；SQLite 提供事务、外键级联和可恢复的单文件边界，不需要后台服务。

**规则**：

- 会话首条消息通过事务写入；
- `messages.conversation_id` 外键级联删除；
- `schema_migrations` 记录版本；
- 迁移兼容旧会话标题和单模型别名，补齐 `model_alias`、`default_model`、`model_aliases`、上下文/输出/推理预算设置，以及带 `message_id` 的 `conversation_attachments` 表；
- 每次 schema 变更必须增加迁移测试和删除/隐私边界测试。

**代价**：不适合多设备同步或多人并发；数据库文件属于用户本地数据，清空和删除操作必须保持明确。

## D-011：模型别名按模型维护，界面即时生效，会话保留快照

**状态：Accepted**

**决策**：设置保存 `default_model` 和 `model_aliases`（原始模型名到显示别名的映射）。设置保存后，当前会话标题、消息标识和侧边栏立即解析新的别名；新建会话时仍将当时的显示名写入 `conversations.model_alias` 快照，旧快照不被数据库回写。

**原因**：一个 Ollama 实例可能同时有多个模型，需要分别命名；用户修改别名后应立即看到结果，而历史导出仍需要保留创建时的可追溯显示名。

**代价**：当前显示名与历史快照可能不同；模型别名不是 Ollama 的真实模型名，所有请求仍使用原始模型名。

## D-012：思考内容默认不落盘

**状态：Accepted**

**决策**：`saveThinking` 默认关闭。关闭时新保存消息只写正文；开启后才写入 `messages.thinking`。已保存的数据不会因关闭开关自动删除。

**原因**：思考内容可能很长，也可能包含用户不希望长期保留的中间推理；默认只保留用户实际需要的正文可以减少磁盘占用和隐私暴露。

**代价**：关闭设置后无法恢复未保存的思考内容；用户需要在设置中明确承担保存成本。

## D-013：使用依赖无关的安全 Markdown 子集

**状态：Accepted**

**决策**：`MarkdownContent.tsx` 使用 React 节点解析有限 Markdown，不使用 `dangerouslySetInnerHTML` 或重量级编辑器；标题、段落、粗体、斜体、删除线、列表、引用、分隔线和受限链接可渲染，代码围栏和数学公式保持文字。

**原因**：聊天输出需要基本可读性，但不需要执行代码、渲染公式或加载嵌入式网页；React 节点天然避免把模型输出当作 HTML。

**代价**：不是完整 CommonMark/GFM 实现，复杂表格、脚注、代码高亮、公式和嵌入内容不保证渲染；扩展语法必须先评估安全边界和主线程成本。

## D-014：自定义无边框标题栏

**状态：Accepted**

**决策**：Tauri 窗口设置 `decorations: false`，前端绘制标题栏；通过 `startDragging`、`toggleMaximize`、`minimize` 和 `close` 提供窗口行为，并在 `default.json` 只开放对应权限。

**原因**：统一全屏布局和品牌视觉，消除系统标题栏与内容区之间的额外空白；同时保留 Windows 基本窗口操作。

**代价**：需要维护拖动区域、双击最大化、按钮命中区域和不同主题下的可见度；任何新增窗口能力都必须显式增加 Tauri capability 权限。

## D-015：诊断默认仅在 Debug 开启

**状态：Accepted**

**决策**：Rust 诊断默认由 `debug_assertions` 决定，Release 通过 `OLLMIN_DIAGNOSTICS` 显式开启；前端默认 Debug 记录，Release 只有 `localStorage['ollmin:diagnostics']` 明确开启才记录。

**原因**：性能优化需要观察 T0/T1/T2/T3、首字、首次绘制、终止和长任务，但普通用户不应持续承担 console、事件和内存记录开销。

**代价**：用户在 Release 中排查问题前需要显式打开开关；诊断记录是本机临时数据，不应作为遥测上传。

## D-016：Debug 保留控制台，Release 隐藏控制台

**状态：Accepted**

**决策**：`src-tauri/src/main.rs` 使用 `cfg_attr(not(debug_assertions), windows_subsystem = "windows")`。Debug 构建保留终端，Release 构建隐藏 Windows 控制台。

**原因**：开发阶段需要直接查看 Rust/Windows 日志；发行版不应让用户看到调试终端，也不应误把它当作客户端主动启动的额外工具。

**代价**：Debug 版本的窗口行为与 Release 的外观不同；排查发布版问题时应使用显式诊断开关和日志，而不是依赖控制台。

## D-017：测试优先覆盖协议边界和存储边界

**状态：Accepted**

**决策**：Rust 测试覆盖 NDJSON 分片/多行/错误、流批处理、取消、档位、历史裁剪和 SQLite 迁移/级联/思考隐私；Vitest 覆盖 Markdown、消息、指标、历史和流合并。真实 Ollama 只做手工或基准验证，不把模型正文当稳定断言。

**原因**：客户端最容易回归的不是某次模型回答，而是协议边界、请求状态、数据迁移和 UI 增量更新。

**当前验证入口**：

```powershell
npm run test
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo test --manifest-path src-tauri/Cargo.toml
```

## D-018：上下文大小作为独立设置覆盖性能档位

**状态：Accepted**

**决策**：设置页提供 4K、8K、16K 三个上下文档位，并保存 `output_token_limit` 与 `reasoning_token_limit`。聊天和诊断请求继续使用性能档位决定思考开关和历史裁剪，再将这些设置覆盖或组合为 Ollama `options.num_ctx` 与 `num_predict`。

**原因**：上下文窗口会影响内存占用和长对话能力，不应被“快速/平衡/推理”三个复合档位完全绑定；低配设备用户可以在保持同一推理策略的同时主动选择资源上限。

**代价**：更大的上下文可能增加内存占用和提示词处理时间；设置变更不会改写已保存会话，只影响后续请求。

**代价**：当前没有完整 Playwright 桌面 E2E；浏览器预览不提供 Tauri IPC，因此桌面启动、真实 Ollama 和安装包仍需要额外冒烟测试。

## D-019：附件按用户消息归属，并只向当前请求注入受限上下文

**状态：Accepted**

**决策**：支持 PDF、DOCX、XLS/XLSX 本地附件；单次最多三个、单文件最多 20 MiB。附件解析结果在 Rust 中保留完整内容，前端仅接收摘要。发送时将附件绑定到具体 `message_id`，后续消息不会自动重复使用；聊天请求只从当前消息指定的附件中选择受限相关片段。

**原因**：把附件保留为全局会话状态会使后续问题隐式重复发送文件内容，既增加 token 和等待，也不符合最小披露原则。按消息归属可以恢复历史显示，并让上下文边界可解释。

**代价**：为恢复附件参考内容，解析后的正文片段和元数据会以明文写入本机 SQLite；原始文件和路径不保存。附件解析、持久化、删除级联和缓存生命周期必须受限并接受隐私测试。

## D-020：附件解析、暂存缓存和首次请求失败保持有界

**状态：Accepted**

**背景**：附件解析会在本地读取压缩文档、PDF 页面和工作表。用户可能反复选择文件但不发送，或在首个会话已经写入后遇到 Ollama 连接失败；如果没有显式边界，解析峰值和会话状态都会逐步偏离预期。

**决策**：

- PDF 在逐页累计文本时检查总字符上限；DOCX 保留条目、XML 和正文上限；Excel 在累积非空单元格、原始文本和渲染行内容时即时检查上限，不能等整张工作表完成后才拒绝。
- 已解析附件只作为发送前暂存。成功写入 `conversation_attachments` 后立即从 Rust 暂存缓存释放；用户移除附件、切换会话、创建新会话或请求失败时也释放对应 ID。
- 新会话创建和首条消息写入成功后，即使随后 `start_chat` 失败，也保留该会话引用；只有创建事务未成功时才清除新会话状态。

**原因**：限制应作用于内存增长发生之前；SQLite 已保存的附件可在后续请求中重新读取，不需要同时保留一份暂存副本。保留已写入会话可以避免首次连接失败后重复创建会话。

**代价**：发送后再次使用附件需要从 SQLite 读取并反序列化；缓存释放失败会以本地错误返回，但不回滚已经成功的数据库写入。

**验证**：Rust 覆盖附件总量、缓存 ID 释放和取消边界；Vitest 覆盖首次请求失败时“已持久化则保留、未持久化才重置”的状态规则。

## D-021：Runtime 先以 crate 内平台边界落地

**状态：Accepted**

**决策**：在直接迁移到 Cargo workspace 之前，先在 Ollmin crate 内建立 `platform::runtime::ModelRuntime`、`OllamaLocalAdapter` 和 `platform::contracts`。Tauri command 只依赖 Runtime 的健康检查、模型列表、预热、一次性聊天和流式聊天接口；固定本机地址与 `/api/*` 路径由适配器维护。

**原因**：阶段 2 需要降低一次性目录迁移的回归风险。保留 crate 内边界可以先验证请求、事件和错误语义，再在后续阶段按需拆分 Runtime 模块。

**代价**：Rust 与 TypeScript 的契约仍需分别维护，跨语言自动生成尚未引入；后续拆 workspace 时要保持当前 trait 和 serde 字段兼容。

## D-023：前端 IPC 契约采用 canonical 模块并保留兼容转出

**状态：Accepted**

**决策**：将前端稳定 IPC 数据形状集中到 `src/contracts/ipc.ts`；根目录 `src/types.ts` 暂时只做 `export *` 兼容转出，现有 feature、API 和组件逐步改用 canonical 路径。共享 UI 基件从无行为变化的小组件开始抽取。

**原因**：先统一依赖方向，再进行产品壳拆分，能避免旧引用在重构中散落或一次性改动过大；兼容转出让未迁移的外部/测试引用保持可用。

**代价**：短期存在一个兼容入口；新增契约应只写入 canonical 文件，并通过构建和类型测试确认没有循环依赖。

## D-032：Ollmin UI几何偏好与业务设置分离

**决策**：侧栏宽度/宽窗折叠和正文手动宽度只使用 `ollmin.ui.*` localStorage键；校验有限数值、宽度范围并按当前可用空间裁剪。窄窗自动折叠和临时展开不覆盖宽窗偏好，拖动按帧更新、完成才持久化，取消回退。主题与隐私等业务设置继续由SQLite保存/取消，不增加schema迁移。

**原因**：几何是可恢复的本地外观状态，读取或写入失败应允许继续聊天。共用菜单和模态只处理portal、顶层键盘和焦点；App继续拥有会话动作、失败反馈及未发送草稿确认，避免视觉重构搬动聊天请求生命周期。

**代价**：偏好失败时本次外观仍可用，但重启可能回默认；草稿仅在当前界面受确认保护，不增加会话级草稿落盘、工作区或归档数据语义。

## D-033：设置采用草稿预览与显式保存

**决策**：四分类设置复用原有SQLite业务保存接口；主题和会话字号在弹窗内预览，放弃恢复已保存值，业务设置不改即时保存。字号是12–22px的UI偏好，使用 `ollmin.uiFontSize`，不增加数据库字段。保存时先写字号，失败不提交业务设置；业务保存失败尝试恢复旧字号，失败原因明确显示且保留草稿。

**原因与代价**：沿用现有保存/取消语义，无迁移或新依赖。localStorage与SQLite不是跨存储事务；回滚若也失败会明确提示，不能宣称原子保存。首次初始化采用中性遮蔽，在内容显示前应用保存主题；仍需原生启动画面验证。

## 未采用的方向

| 方向 | 当前不采用的原因 |
| --- | --- |
| 直接在 WebView 请求 Ollama | 跨域、取消、错误和本机地址约束不集中 |
| OpenAI 兼容层作为核心 API | 丢失 Ollama thinking/指标语义，增加适配层 |
| 自动标题、摘要、记忆和向量索引 | 额外模型调用、上下文和磁盘成本不符合低配定位 |
| MCP、Shell、文件和网页工具 | 扩大权限和隐私边界，破坏“只聊天”安全约束 |
| 无限历史或无限上下文 | 低配设备内存与首字延迟不可控 |
| 完整 Markdown/代码/公式引擎 | 体积、渲染成本和不可信输出风险高于当前需求 |
| 默认并行请求或多模型常驻 | 可能导致低显存设备换入换出，降低总体体感速度 |
